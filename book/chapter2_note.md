## tips
1. 系统提示词和工具定义一旦确认就不要轻易修改
    - MCP 第4章
2. 使用框架api，而不要自己定义角色
    - 破坏了训练时的固定格式
3. 动态信息永远要加入末尾
    - agent状态栏

## 注意力
1. 模型对开头和末尾分配更多的注意力

## 常见的破坏KV cache的行为
1. 动态系统提示词
    - 比如时间戳放进系统提示词中
    - 破坏：KV cache
2. 动态用户配置
    - 比如用户api调用次数等
    - 同上
3. 工具定义的动态排序
    - 同上
4. 滑动窗口的对话历史
    - 破坏1: kv chace
    - 破坏2: 忘记历史，可能丢失关键信息

## agent 状态栏
1. reason: AI擅长检索，但不推理
2. 隐式状态提炼为可直接使用的显式知识
3. 包括：
    1. 任务规划（todo）
    2. 时间侧信道（时间，位置，附在每一句对话）
    3. 环境状态
4. （环境状态）位置
- 最后。使用 来源标记 <agent-status> 标记
5. 两种实现
    1. 每一次替换（kv cache冲突）
    2. 持续加在末尾（context长）
    3. 考虑点：
        1. 状态长度，轨迹长度
        2. 两次更新间产生信息多不多（多的话应该要保存之前的信息）
6. tips：
    1. 用代码维护
    2. 不要删除原始上下文
    3. 属于“上下文压缩”的概念

## 压缩
### why
1. 长度成本
2. 思考质量
3. （缓解模型的上下文焦虑）

### 上下文学习的缺点
- 检索，而不是推理
- 因此压缩后总结，有一定必要性

### 压缩 与 kv cache 的冲突
1. head保持不动
2. 压缩对象是 tool res
3. 权衡，什么时候压缩

### 压缩策略对比（针对搜索结果）
1. 单篇压缩
2. 组合压缩
3. 上下文/任务 感知压缩
4. 带引用的上下文 感知压缩
5. 自适应窗口化
    1. 阈值触发
    2. 批量压缩
    3. 防重复保护

### 生产级分层压缩
1. 大工具结果存磁盘，模型看摘要。
2. 工具结果一旦压缩，就冻结不再改变，保证kv cache.
3. 没用的直接删，不做摘要（如何判断呢）
4. 服务端删除
5. git log式摘要
6. 全量压缩
